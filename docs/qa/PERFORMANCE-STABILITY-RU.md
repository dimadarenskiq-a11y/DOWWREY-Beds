# DOWWREY Beds 1.8.0 — производительность и стабильность

Цель этого этапа — обычная одиночная игра и выделенные Fabric-серверы на 50–100 игроков без постоянной нагрузки от мода.

## Основные изменения

- Fabric API обновлён до **0.162.0+26.3** — это текущий стабильный релиз ветки 26.3 на момент подготовки 1.8.0.
- Fabric Loader остаётся **0.19.5**, совместимый с Minecraft 26.3.
- Fabric Loom остаётся **1.18.2** как проверенный для текущего проекта toolchain.
- Java target: **25**.
- Gradle 9.7.1.
- Включён Gradle build cache.

### Серверная оптимизация

- `SavedData` остаётся основным постоянным хранилищем Minecraft.
- Дополнительный JSON recovery-backup больше не пишется на каждую мутацию. Он дебаунсится до одного обновления каждые 30 секунд после изменений и принудительно создаётся при остановке сервера.
- `BedSavedData.get(server)` не выполняет файловые операции.
- Открытие Friend Bed selector больше не вызывает отдельный подсчёт кроватей для каждого игрока. Количество кроватей для всех онлайн-игроков вычисляется одним проходом по данным.
- Поддерживается до 256 записей в payload списка игроков, что покрывает серверы на 50–100 игроков с запасом.
- Запросы списков ограничены сервером; значение по умолчанию — 10 ticks.
- Открытие Friend Bed selector ограничено отдельным rate limit 10 ticks. Обычное сохранение кровати этот лимит не получает, поэтому вторую кровать можно сохранить сразу.
- Изменение/удаление/выбор кровати, ответы на Friend Bed, respawn и старт телепорта имеют короткий серверный action guard 2 ticks (100 мс) против packet spam без заметной задержки для обычного игрока.
- Friend Bed pending requests ограничены 32 на получателя и очищаются раз в секунду.
- Телепортационные Map-структуры содержат только активные телепортации/cooldown и очищаются при disconnect/server stop.
- Safe-position checks выполняются только при необходимости: открытие списка, respawn и телепорт. Чанки ради статуса кровати не загружаются.
- При отображении незагруженной точки она не считается сломанной до фактической проверки.
- Teleport HUD кеширует изменяющийся текст вместо форматирования строки каждый кадр.

## Стабильность

- Все игровые действия валидируются на сервере.
- Отмена телепорта выполняется только по реальному урону.
- При отмене или disconnect стоимость телепорта возвращается.
- При полном инвентаре возвращённое Око безопасно выбрасывается рядом с игроком, а не теряется.
- Server config при повреждении файла не блокирует запуск сервера: используются безопасные значения по умолчанию и пишется предупреждение в лог.
- Схема `SavedBed` версии 3 поддерживает старые сохранения через совместимый codec.

## Ограничения проверки

В текущей среде нет JDK 25 и внешнего Gradle-кэша, поэтому настоящий `build` и нагрузочный тест 50–100 игроков должны быть выполнены в IntelliJ IDEA на Temurin 25.0.4/25.0.4.1 и на отдельном dedicated server.
